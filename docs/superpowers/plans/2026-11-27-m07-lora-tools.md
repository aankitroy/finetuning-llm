# M7 · LoRA with real tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Module M7: the learner configures LoRA in mlx-lm and PEFT, trains the M5 task on Qwen2.5-1.5B-Instruct with both on identical batches, compares speed/memory/quality, and reloads each saved adapter.

**Architecture:** Same layout as M6 (`starter/`, `solutions/`, root copies, `tests/`, `video/`). `train.py` imports M5's `train.py` as a library (as M6 does) for data, scoring and batching with the learner's M5 code, builds one list of padded batches, and drives `mlx_lm.tuner.trainer.train` (custom `iterate_batches` that yields those batches) and a PEFT model trained with M5's `train_loop`-style loop.

**Tech Stack:** mlx 0.32.5, mlx-lm 0.32.2 (macOS arm64 only), peft 0.22.0, transformers 5.23, torch 2.15.

**Spec:** `docs/superpowers/specs/2026-11-27-m07-lora-tools-design.md`

## Global Constraints
- Model `Qwen/Qwen2.5-1.5B-Instruct`; data read in place from `modules/m05_full_finetune/data`.
- Both tools: rank 8, alpha 16 (scale 2.0), q/k/v/o in all 28 layers, dropout 0, batch 8, bf16, same batches in the same order, same steps, same lr schedule (10 warmup steps, cosine), loss on answer tokens only.
- Each full run's peak under ~18 GB; each under ~10 minutes.
- mlx imports only inside functions or behind `sys.platform == "darwin"`; on Linux the mlx tests skip and `train.py --tool peft` still works.
- Never touch the learner's `exercises.py`, `answers.toml`, `lesson.ipynb`, `.progress`, `outputs`; real runs use `FTCOURSE_OUTPUTS` pointing at a temp folder.
- Beginner style as M1–M6: "In plain words:" docstring, `# 1.` steps and "section N" in every exercise; **What each line does** after every code cell; bold terms; README glossary + syntax table.

## Measured in the spike (2 epochs = 100 steps, lr 2e-4, bf16)
| | val loss before → after | time | tokens/sec | peak |
|---|---|---|---|---|
| mlx-lm | 1.060 → 0.659 | 120 s | ~480 | 6.1 GB (`mx.get_peak_memory`) |
| PEFT (MPS) | 1.103 → 0.660 | 64 s | ~900 | 20.6 GB (`torch.mps.driver_allocated_memory`, cache grows) |
Trainable 2,179,072 of 1,545,893,376 = 0.141% in both. PEFT's peak must be brought under 18 GB (try `torch.mps.empty_cache()` every few steps and/or `PYTORCH_MPS_HIGH_WATERMARK_RATIO`); measure the held-out loss with one shared, course-owned function for both tools so "before/after" is comparable.

## Review Focus
1. Learner returns `alpha` instead of `alpha / r` as mlx `scale` (or `scale` to PEFT) → a run that trains with 8× the update; tests must catch both with a clear message.
2. Learner's `tokens_per_sec` counts padded positions → numbers inflate on uneven batches; test with a mask that has padding.
3. Adapter reloaded but not applied (e.g. `load` without `adapter_path`, or PEFT base returned) → outputs equal base; the reload-equality check plus "differs from base" catches it.
4. mlx-lm or the model missing, or Linux → `train.py` prints what to install/download instead of a traceback.
5. A run from older code or `--tiny` must not pass the checkpoint (sha256 of `exercises.py`, `tiny` flag), as in M6.
